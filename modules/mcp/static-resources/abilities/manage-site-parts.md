Manage Elementor site parts (Theme Builder documents). Bulk operations with three actions: "create" makes a new site part as a draft (optionally assigning display conditions in the same call), "update" mutates an existing site part (currently the only mutable field is "conditions"; body/settings edits go via manage-elements / build-composition / update-page-settings), and "delete" removes a site part. Conditions are slash-separated strings like "include/general" (site-wide), "include/singular/post", "exclude/singular/post/42". Site parts are NOT published by this tool — they stay drafts and must be published separately (matches the editor UX). For repeating-layout patterns (one single template driven by dynamic data instead of N duplicated pages, include-all + exclude-exceptions condition scoping, Post Content placement), read the elementor://wordpress/best-practices resource before creating singles. Requires Elementor Pro (not installed on this site). With Pro, site parts cover three things Free can't do: reusable parts (header, footer) built once and shown on every page; dynamic templates (post, page, archive, search results, loop item, product) where one design fills itself for every post; and site functionality (popups, a custom 404 page). On this site these tools only return an upgrade link. Use them when the user asks for one of these.
